# 第一轮实验设置自查

对照的是 `analysis/2_查看是否跨模态误差与不同的bit设置有关.md` 里对「已经跑完的第一轮」的复述，以及 `results/01_component_interaction/` 里的三份 JSON 和 `01_component_interaction.md`。

结论：对得上。可以进入第二轮计划。下面只记核对过的对应关系，以及两处不影响这个判断的口径。

## 对应得上的部分

第一轮实际跑的是八格、同一套 RTN、只量化权重、4 bit、group 128、非对称。被打开的组件共用这一个比特。没有 AWQ、GPTQ，也没有 PRISM 的保列。样本是 32 条 ShareGPT4V-COCO，batch size 1，种子 42。三个模型的 `sanity_flags` 都是空的。交互定义是 \(I_{A,B}=\mathcal{L}(A\cup B)-\mathcal{L}(A)-\mathcal{L}(B)\)，正号表示联合量化比相加更糟。

LLaVA-OneVision 的 JSON 与分析里点名的数字一致：

- 只量化视觉时，`vision_out` 的 MSE 是 0.7165，logit KL 是 0.008378。
- 只量化投影、只量化语言模型的 logit KL 分别是 0.0002085 和 0.03095。
- `llm_late` 上 \(I_{V,L}=-0.8177\)。
- logit KL 上 \(I_{V,L}=-4.55\times 10^{-5}\)。

探针顺序也一致：`vision_out` 上交互是 0，`proj_out` 和 `llm_early` 接近 0，`llm_mid` 很小，`llm_late` 上出现负的非加性，logit KL 又回到接近 0。分析没有把 `llm_late` 的 -0.82 当成已经发现了有害交互，这和结果文档自己的读法一致。

三个模型的 logit 比例也来自同一张结果表，不是分析另算的一套实验：

| 模型 | 结果文档里的 \(I_{V,L}/(\mathcal{L}(V)+\mathcal{L}(L))\) | 分析中的写法 |
| --- | --- | --- |
| LLaVA-OneVision | -0.1% | -0.1% |
| Qwen2.5-VL | -2.8% | -2.8% |
| InternVL2-8B | -8.5% | -8.5% |

Qwen 的原始 \(I_{V,L}\) 是 -0.001295。除以 \(\mathcal{L}(V)+\mathcal{L}(L)\approx 0.0467\)，就是大约 -2.8%。InternVL 的原始值是 -0.003179，除以约 0.0373，就是大约 -8.5%。三个模型都没有 \(I_{V,L}>0\)。

组件划分按各模型的算子来，不是硬套 LLaVA 的 `mm_projector`。JSON 里写了：Qwen2.5-VL 的 V 是 `visual.blocks`、P 是 `visual.merger`；InternVL2 的 V 是 `vision_model`、P 是 `mlp1`。分析里的「当前组件定义」指的就是这一套。

因此，分析前半段否定的假设，就是这一轮真正测过的假设：在全部 W4 时，视觉和语言模型的量化误差会不会合成额外伤害。这个假设在 logit KL 上没有成立。

## 不影响判断的两处口径

分析把 \(I_{V,L}\) 写成 -0.1%、-2.8%、-8.5%。这是交互除以两个单组件损失之和，不是 JSON 里的原始差值。原始差值仍是上面的 \(-4.55\times 10^{-5}\) 这一档。符号和「接近 0、略偏补偿」没有反转。

样本在配置和结果文档里写的是 ShareGPT4V 的 COCO 图文，不是任意 COCO 子集。LLaVA 这一路用的是适配器里的 `pad` 单图。分析没有再写这两句，但也没有改成另一种数据或另一种图像切分。
